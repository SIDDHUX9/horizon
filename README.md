### Mainnet blockers

7. Rotate any locally generated wallet keys that may have existed in ignored `.env` files.
8. Complete an external security review before advertising mainnet readiness.

## Executive overview

Conventional DeFi lending requires heavy overcollateralization because public smart contracts cannot assess borrower creditworthiness. Traditional underwriting, meanwhile, demands intrusive disclosure of private financial records.

Horizon's design uses Midnight's dual-ledger model:

* **Borrowers** keep income, debt, and ratios private and prove only that they satisfy a lender's published thresholds.
* **Lenders** publish transparent pool parameters and verify eligibility as a boolean proof result.
* **Smart contracts** are intended to verify the underwriting inequalities and settle loan state without publishing raw financial data.

The Compact contract already contains the core inequality logic. The web app provides an explicitly labelled local simulator for user experience review and a separate production client that refuses to attach until a verified deployment exists.

## Intended public vs. private ledger model

```
┌───────────────────────────────────────────────┬───────────────────────────────────────────────┐
│           PUBLIC LEDGER STATE                 │            SHIELDED WITNESS STATE             │
│        (Visible to anyone on Explorer)        │           (Strictly on Client Device)         │
├───────────────────────────────────────────────┼───────────────────────────────────────────────┤
│ • Lender risk thresholds                      │ • Borrower's actual annual income             │
│ • Pool accounting values                      │ • Borrower's existing liabilities & debts     │
│ • Loan lifecycle status                       │ • Borrower's computed debt-to-income ratio    │
│ • Public loan amount, term, and interest rate │ • Cryptographic blinding salt                 │
│ • Commitment and transaction records          │ • Underlying reason for approval/denial       │
└───────────────────────────────────────────────┴───────────────────────────────────────────────┘
```

**Important:** today's simulator uses SHA-256 commitments in `localStorage`. The Compact circuit uses `persistentHash<FinancialSnapshot>`. These schemes are not interchangeable; the browser client must use the Compact-compatible commitment path before on-chain calls are enabled.

## Compact smart contract architecture

The contract source is `src/contracts/horizon.compact`. It exposes five circuits:

1. `createLendingPool` — validates thresholds and initializes public pool accounting.
2. `submitFinancialSnapshot` — commits to a private financial snapshot using `persistentHash`.
3. `requestLoan` — recomputes the commitment and asserts income, DTI, collateral, and consistency inequalities in-circuit.
4. `repayLoan` — checks cumulative repayment against principal plus interest using cross-multiplication.
5. `liquidate` — permissionless transition for an expired active loan.

Known contract-level gaps are documented in `wave2.md`, including caller-supplied time inputs, absent token custody, and incomplete repayment economics. These must be resolved before mainnet use.

## Quickstart

### Prerequisites

* Node.js 22.12 or later (required by Midnight.js 5)
* Docker Desktop (optional; needed for local proof-server experiments with proof server 9.0.2)
* A Midnight-compatible wallet for real network work

### Install

```bash
git clone https://github.com/SIDDHUX9/horizon.git
cd horizon
npm install
```

### Verify the compiled contract stack

```bash
npm run verify:artifacts
```

This checks the `compactc` 0.36.1 manifest, all artifact hashes, and the runtime 0.21.0 binding. A mismatch fails closed.

To verify source/binding reproducibility, install Compact toolchain 0.36.1 and run `npm run compile:compact -- --check`. This is read-only and fails if generated bindings, ZKIR, or manifest differ from the committed artifacts. To regenerate keys, run `npm run compile:compact -- --full`; it fails closed unless a complete prover/verifier key set is produced and the pinned client manifest hash matches (use `--update-client-hash` only after reviewing the artifact diff).

### Run all checks

```bash
npm run ci
```

This runs TypeScript checking, artifact verification, unit tests, and a production build. The same sequence runs on pushes and pull requests through `.github/workflows/ci.yml`.

### Run the app

```bash
npm run dev
```

Open <http://localhost:5173>. The default experience is **production mode**: no verified deployment exists, protocol forms are replaced by an offline panel, and circuit calls are disabled. To use the browser-local demonstration, add `?demo=1` to the URL or set `VITE_DEMO_MODE=true` in a local `.env` file (see `.env.example`). Demo mode never submits transactions.

Compiled artifacts are served under `/contracts/` by the Vite dev middleware and copied into `dist/contracts/` during `npm run build`, so the production client can load the exact pinned manifest, keys, and ZKIR. Browser-side chain reads default to the Preview indexer; set `VITE_INDEXER_URL` in a local `.env` for another network. Contract calls continue to use the indexer supplied by the connected wallet.

### Verify the deployment record

```bash
npm run verify:deployment
```

The command checks the contract, deployment transaction, **and** that the transaction deployed that contract. Set `MIDNIGHT_INDEXER_GRAPHQL` and `MIDNIGHT_INDEXER_PROJECT_ID` to use the authenticated official Midnight Indexer; otherwise it falls back to the public Explorer REST API. The command exits non-zero unless all three findings are confirmed. After a real broadcast, the canonical record can only be updated through:

```bash
npm run confirm:deployment -- --address <64-hex-contract-address> --tx <64-hex-deploy-tx>
```

That command re-runs the same verification and refuses to write anything if any finding is missing.

### Local proof server (experimental)

```bash
docker compose up -d horizon-proof-server
npm run preflight:proof
```

The preflight checks artifact integrity and proof-server reachability. It does **not** prove a Horizon circuit or submit a transaction.

## Security and privacy notes

* The Compact circuit uses cross-multiplied `Uint<128>` comparisons to avoid in-circuit division.
* The browser simulator uses SHA-256 commitments; this is not compatible with the Compact circuit's `persistentHash<FinancialSnapshot>`. Production snapshot calls prepare the raw witness in encrypted local private state and let the circuit compute the on-chain commitment.
* The contract does not move NIGHT tokens. All balances are accounting values.
* `current_time` is caller-supplied in several circuits and is not yet bound to an authoritative ledger clock.
* The DApp Connector, indexer, artifact integrity checks, and production circuit wrappers are real. All circuit calls are hard-gated by `assertVerifiedDeployment()`, which currently fails because no deployment is verified.
* The private-state password is held in session memory and passed only to the local private-state provider. It is never written to `localStorage`, an API request, or a log.
* Do not treat the current build as audited, auditable, or safe for real funds.

## Deployment

The static SPA can be deployed to Vercel or any static host. The build targets modern browsers (`esnext`) because Midnight.js 5 and ledger-v9 initialise WebAssembly with top-level await; `vite-plugin-wasm` emits the WASM assets. The `/api/midnight/*` endpoints in `scripts/vite-midnight-plugin.js` only exist in the Vite dev server, so deployment actions are not available in a static production build. A real backend or serverless functions are required before exposing any deploy workflow.
